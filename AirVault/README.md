# AirVault

AirVault 是优先通过二维码交换数据的 Android 多链离线签名应用，也支持手动输入请求。它不会请求网络权限。首次创建会生成 24 词 BIP-39 助记词，也可恢复 12/15/18/21/24 词英文助记词。启动时先显示 Splash，并在后台检查加密数据库；已有钱包直接进入钱包卡片首页，无钱包时进入创建/导入入口。数据库读取失败时停留在 Splash 并提供重试。首页卡片下方可创建新钱包。点击卡片进入地址列表；首次查看经生物识别解锁后，列出各链公开地址。

支持 Ethereum、BNB Smart Chain、Polygon PoS、Arbitrum One、OP Mainnet、Base、Avalanche C-Chain、Gnosis Chain、Cronos、Sonic，以及 Bitcoin、Solana、TRON、Zcash，共 14 条链、16 种地址。EVM 网络共用 `m/44'/60'/0'/0/0` 地址，并校验请求 `chainId`；Solana 使用 `m/44'/501'/0'/0'`，TRON 使用 `m/44'/195'/0'/0/0`。当前使用各链的第一个账户，地址浏览器可查看该路径下 Receive / Change 各 100 个地址。

Zcash 支持主网透明 P2PKH 地址（`t1…`），使用 BIP-44 路径 `m/44'/133'/0'/0/0`、压缩 secp256k1 公钥和双字节前缀 `0x1cb8`。Receive 与 Change 分别为 `m/44'/133'/0'/0/index`、`m/44'/133'/0'/1/index`，各显示索引 0–99；可复制、显示地址二维码和同步至 AirWallet。TrustWallet 不支持 Zcash，其同步按钮禁用；MetaMask 配对仅限 EVM 链。暂不支持屏蔽地址、统一地址、余额查询或 Zcash 交易签名，详情页不显示签名入口。

Bitcoin 支持以下三种主网地址，三种类型同时显示在钱包地址列表中，点击进入对应详情；请求页也可切换类型，默认使用 SegWit：

| 地址类型 | 脚本 | 派生路径 | 前缀 |
| --- | --- | --- | --- |
| Legacy | P2PKH | `m/44'/0'/0'/0/0` | `1…` |
| SegWit | 原生 P2WPKH | `m/84'/0'/0'/0/0` | `bc1q…` |
| Taproot | BIP-86 P2TR | `m/86'/0'/0'/0/0` | `bc1p…` |

同一助记词分别派生三种地址；每个钱包独立记住所选类型，保存于加密 Room 数据库。解锁地址时缓存三种公开地址及公钥，切换类型无需再次生物识别；打开不同类型时清除原签名请求并更新观察账户导出。AirWallet 导出仅包含当前选中的 Bitcoin 类型，需要重新扫码导入以使用新的地址。数据库从版本 1 升至版本 2 时保留已有钱包及助记词，并将地址类型设为 SegWit。

创建钱包时先生成 `java.security.SecureRandom` 的 4096 字节随机数。用户确认说明并授权相机和麦克风后进入画板；在绘制期间，后台从后置和前置摄像头各采集三张最低受支持分辨率的 YUV 图像（每秒一张）。麦克风只累计超过静音阈值的 16 kHz 单声道 PCM 数据，直到收集满五秒；有陀螺仪的设备以 Android 的 `SENSOR_DELAY_NORMAL` 采样，至少采集五秒，并累计 1000 条有明显变化的读数，静止时进度暂停；普通频率下可能需要数分钟。点击确认后，按随机数、后置照片、前置照片、麦克风、陀螺仪、手绘轨迹的固定顺序，使用 SHA3-256 的分段 `update` 处理原始数据，得到 32 字节 BIP-39 熵。原始图像、陀螺仪事件和音频不写入磁盘；退出流程会清理本轮内存数据。设备没有陀螺仪或无法注册传感器时跳过该来源，继续创建钱包。

采集前的说明页会解释所需权限、用户操作和数据用途，点击“继续”后才申请相机与麦克风权限。画板下方用单行图标和百分比显示随机数、摄像头、声音、陀螺仪与绘制进度；摄像头进度合并计算前后共六张图像。解锁地址后，应用缓存各链公开地址、公开派生密钥和 chain code，浏览地址与配对无需再次进行生物识别；缓存不包含助记词、种子或私钥。Solana 使用 hardened 派生，解锁时预先生成两个分支的公开地址。查看助记词和每次签名仍要求生物识别。

钱包名称、助记词密文和当前钱包选择使用 Room 3.0.3 的 Entity、DAO 和事务保存到 SQLCipher 4.20.0 数据库。数据库密码由 Android Keystore 中不可导出的硬件 HMAC-SHA256 密钥，使用固定的用途标识派生，不写入文件或 SharedPreferences；SQLCipher 连接关闭时清理密码数组。助记词在数据库加密之外，继续由需要每次强生物识别授权的 Android Keystore AES-GCM 密钥加密。旧版 SharedPreferences 中的加密助记词会自动迁移为“钱包1”，数据库事务提交后才删除旧副本。创建、恢复、查看助记词和每次签名都需要设备强生物识别。优先尝试 StrongBox，设备没有 StrongBox 时要求普通 Android Keystore 密钥由安全硬件承载；不支持硬件密钥的设备不能创建钱包。请先在设备系统设置中录入强生物识别。内存中的助记词长期副本使用 Lazysodium Android 5.2.0 的 `sodium_malloc` 分配，并在未读取时设为不可访问；释放时由 `sodium_free` 擦除。派生种子、私钥字节和熵的临时数组也调用 `sodium_memzero` 并清零 JVM 数组。锁屏或切到后台后，同一应用进程内保留受保护副本和验证进度，返回时重新遮盖助记词；签名结果仍会清空。页面显示和 web3j、bitcoinj 等链库仍需短暂使用 JVM `String`、`ByteArray` 和 `BigInteger`，无法保证这些临时副本被完全擦除，也不能把派生私钥视为始终在安全硬件内。系统回收进程后，尚未保存的新助记词无法恢复。备份和设备迁移已禁用；卸载应用前必须保留纸质助记词。

首页的钱包以 Card 列表显示，下方“创建新钱包”进入生成或导入流程。点击任一钱包进入地址列表，标题包含链图标、链名称和地址类型，副标题显示公开地址。点击列表上方的钱包名称可修改为 1–30 个字符，保存后同步更新首页卡片；列表页不再提供签名请求按钮。每次新增均插入独立记录；切换时清空上一钱包的公开地址、二维码和签名请求，当前选择会持久化。销毁操作只删除当前钱包，仍有钱包时自动切换到剩余钱包；删除最后一个钱包才移除助记词 AES 密钥。

钱包地址列表右上角菜单提供“添加自定义链”，填写链名称、派生路径和地址格式，默认为 EVM；EVM 格式还须填写 ChainId，范围为 1–9223372036854775807 的十进制整数，保存后在地址详情显示。其他地址格式无需填写 ChainId。地址格式可选 EVM、Bitcoin Legacy / SegWit / Taproot、Solana、TRON、Zcash 透明地址；仅填写路径不能确定地址编码。名称去除首尾空格后须为 1–30 个字符，不能与内置或已有自定义链重名；路径支持 `'`、`h`、`H` 强化标记并统一保存为 `'`，Solana 每段均要求强化派生。

自定义链配置通过 Room 保存在同一个 SQLCipher 数据库中，应用于本机所有钱包，地址分别从各钱包助记词派生；数据库升级保留已有钱包、助记词密文、当前钱包和 Bitcoin 地址类型。版本 3 升至 4 时为自定义链增加 ChainId；已有配置保留空值，不猜测网络编号。保存后重新解锁以生成公开地址，取消解锁仍保留配置。列表首个地址严格使用所填写的完整路径；地址浏览器替换末两段为 Receive `0/index` 和 Change `1/index`，保留各段强化标记，分别显示索引 0–99。缓存仅保存公开地址和公钥。自定义链可复制、显示地址二维码和浏览派生地址；尚未接入配对协议和交易签名。

地址详情显示链图标、名称、地址和导出路径；点击地址右侧二维码图标打开地址二维码对话框。右上角菜单提供“复制地址”“地址浏览器”和“扫描签名请求”；详情页底部另有固定的“扫描签名请求”按钮，不随内容滚动。助记词与销毁操作位于钱包地址列表右上角菜单。

详情页可进入对应钱包的配对页面，二维码上方显示“用 XX 钱包扫描二维码”：

- AirWallet：使用单张静态 AV1 二维码，仅包含当前详情对应链的公开地址和公钥；Bitcoin 只导出当前 Legacy / SegWit / Taproot 类型。扫码后 AirWallet 仅更新该链并切换到该链，保留其他已导入账户。需要支持单链公开账户包的新版 AirWallet；仍兼容旧版多链导入。交易请求和签名结果仍可分帧。
- MetaMask：仅 EVM 网络可用，使用其二维码硬件账户模式支持的 UR `crypto-account`（公开密钥、主指纹和原始派生路径），通过“连接硬件钱包”的二维码入口导入。这里只同步账户，尚未接入 MetaMask 的 `eth-sign-request` / `eth-signature` 交易往返；交易签名继续使用 AirWallet。
- TrustWallet：显示当前公开地址，供添加对应网络的只读钱包时扫码；不包含私钥。已按 Android 26.45.8 的只读钱包网络列表核对，支持本项目的 10 条 EVM 链、Solana 和 TRON。Bitcoin（Legacy / SegWit / Taproot）及 Zcash 未出现在该入口，按钮禁用。完整名单、版本及核对依据见 [Trust Wallet 兼容性记录](docs/TRUST_WALLET_COMPATIBILITY.md)。

地址浏览器使用 Receive / Change 两个 Tab，分别显示索引 0–99 的地址卡片，每张显示地址及完整路径。点击地址卡片打开该派生地址的二维码对话框，下方“复制地址”按钮将所选地址复制到剪贴板。标准 secp256k1 路径从 `…/0/index` 和 `…/1/index` 公开派生；Solana 保留 hardened 标记，使用 `m/44'/501'/0'/index'` 和 `m/44'/501'/1'/index'`。浏览器用于查看派生地址，当前交易签名仍限制为各类型默认的第一个地址。

Android Keystore 保护数据库密码的派生密钥及加密助记词的 AES 密钥。BIP-32 派生出的 secp256k1 私钥需在应用内存中短暂参与签名，不能宣称私钥本身不可从安全硬件导出；因此仍应使用专门的离线设备，并避免安装来路不明的软件。

助记词网格不暴露给 Android 辅助功能语义树，避免常规无障碍读取接口直接取得词语；这也意味着屏幕朗读无法朗读助记词。请在可信设备上使用，勿安装可读取屏幕内容的辅助功能服务。

新建和恢复助记词页面默认以 `***` 遮盖词语，点击网格上的“查看助记词”后才显示。24 词以三列八行紧凑排列。确认离线备份后，应用随机抽取 10 个不重复序号；用户通过页面内字母键盘从 BIP-39 英文词库候选中填满 10 个单词，再点击标题栏右上角的“验证”。候选词区域显示约两行；输入首字母后，只启用词库中可作为第二字母的按键，后续输入也按当前前缀过滤。键盘的 26 个字母在每次进入验证页及验证失败重试时重新随机排列，填写期间保持稳定。错误序号会标出并允许修改；全部正确后进入“设置钱包名称”页面，默认名称为“钱包”加当前已保存钱包数量加一（如“钱包1”“钱包2”），名称可修改为 1–30 个字符；使用生物识别后保存。导入页先选择 12、15、18、21 或 24 词，再通过三列网格和固定在下方的自定义键盘逐词填写；选择候选词后自动跳到下一个空位，点击已填位置可修改。词数较多时可滚动网格，切换词数保留重叠部分，删除的尾部词语不会恢复。填满后点击右上角“下一步”，通过 BIP-39 校验后进入命名页面，失败时可留在原页核对修改。导入页和验证页均不调用系统输入法。导入草稿和待输入前缀仅保留在内存中，切到后台或离开导入流程时清空。应用使用 `FLAG_SECURE` 禁止系统截屏和最近任务预览，返回助记词页时需要重新点击“查看助记词”。

## 离线请求格式

AirWallet 默认使用版本化二进制消息和分帧二维码，格式见 [AirWallet 的协议说明](../AirWallet/README.md#二维码协议-v1)。AirVault 仍接受旧版 UTF-8 JSON 单张二维码或手动输入。EVM 金额、Gas 和 nonce 使用十进制字符串表示链上整数，也接受 `0x` 十六进制字符串。`data` 是十六进制字节串，未提供时为 `0x`。代币转账和合约调用使用目标链的原生交易数据；AirVault 展示原始调用数据，并有限解码常见 ERC-20 方法，但不验证合约执行后的资产变化。

```json
{"type":"eth_personal_sign","chainId":1,"message":"Hello AirVault"}
```

```json
{"type":"eth_transaction_1559","chainId":1,"nonce":"0","to":"0x000000000000000000000000000000000000dEaD","value":"1000000000000000000","gasLimit":"21000","maxPriorityFeePerGas":"1000000000","maxFeePerGas":"2000000000","data":"0x"}
```

旧格式交易使用 `type: "eth_transaction"` 和 `gasPrice`，其余字段相同。旧消息请求若省略 `chainId`，按 Ethereum 主网处理。EVM 的 ERC-20 转账、授权和其他合约调用可放入 `data`，签署前应核对合约地址与调用数据。

Bitcoin 的旧版 JSON 使用以下格式。`unsignedTransaction` 是完整的未签名原始交易十六进制；`previousTransactions` 按输入顺序提供各 UTXO 所在的完整原始交易，AirVault 会核对交易 ID、输出金额与脚本，计算全部输出和费用。AirWallet 产生的二进制请求使用 BIP-174 v0 PSBT，由 AirVault 解析并执行相同的核对。每次只签当前类型首个地址的输入，拒绝混合类型、重复输入或其他钱包的输入。Legacy 和 SegWit 固定使用 ECDSA `SIGHASH_ALL`；Taproot 使用 BIP-340 Schnorr、BIP-341 `SIGHASH_DEFAULT` 和 BIP-86 key-path，无 annex 或脚本树。PSBT 支持完整前序交易、witness UTXO、匹配的 sighash 和派生元数据，拒绝部分签名、其他 sighash、脚本路径及其余不支持的输入字段。交易输出可以承载 OP_RETURN 等代币协议数据，但当前不解析代币语义；尚不支持 P2SH、多签和 Ordinals/BRC-20 的专用签名流程。

```json
{"type":"btc_transaction","unsignedTransaction":"<原始交易十六进制>","previousTransactions":["<输入 1 的完整前序交易十六进制>"]}
```

Solana 使用单签名、无地址查找表的 legacy 或 v0 已编译交易，`transaction` 是 64 字节零签名加消息的 base64 序列化交易。签名账户须是第一个账户（手续费支付账户）且属于本钱包。原生币、SPL 代币和合约指令均可签署；页面逐条展示程序地址、账户和原始指令数据。多签交易和地址查找表交易会拒签。

```json
{"type":"sol_transaction","transaction":"<未签名交易的 base64>"}
```

TRON 使用 protobuf 序列化的未签名交易十六进制，支持 `TransferContract`（TRX）、`TransferAssetContract`（TRC10）和 `TriggerSmartContract`（TRC20 及其他合约调用）。交易须只含一个合约，发起地址须属于本钱包。页面显示合约地址、附带 TRX、原始调用数据和费用上限。

```json
{"type":"tron_transaction","transaction":"<未签名交易的 protobuf 十六进制>"}
```

签名后 AirVault 为 AirWallet 的二进制请求显示分帧二维码，并绑定原请求 ID；旧版 JSON 请求仍返回 JSON 二维码：消息签名包含 `signature`，EVM、Bitcoin、Solana、TRON 交易签名包含可广播的 `signedTransaction`，结果均包含 `from`。Bitcoin 与 TRON 的旧版签名交易是十六进制，Solana 是 base64。旧版结果过长时无法显示在单张二维码中，页面仍显示完整文本。AirVault 不广播交易，也不查询余额、UTXO、区块哈希或 nonce。

目前采用 AirGap Vault 式的离线扫码流程，但此 JSON **不是 AirGap 的可互操作协议**。Bitcoin 前序交易虽可验证内容与交易 ID，但离线设备无法验证 UTXO 是否仍未花费。Solana 与 TRON 的合约调用无法仅凭原始数据推断完整执行效果；签名前必须自行核对。此项目尚未经过独立安全审计，不应直接用于存储大额资产。

## 构建

在 `AirVault` 目录执行 `./gradlew :app:assembleDebug :app:testDebugUnitTest`。需要 Android SDK 37 和 JDK 17 或更新版本。
